# 控制台（WebUI）

控制台是网关自带的管理页面：`webui/` 下的 TypeScript 源码由 Vite 构建成单个 `webui/dist/index.html`，再由 `src/http/static.rs` 在编译期嵌入二进制，由 `GET /` 返回。本文只讲**界面本身**的设计与结构；路由、字段与错误码见 [API 端点](api.zh-CN.md)。

## 文件结构

| 文件 | 职责 |
| --- | --- |
| `webui/index.html` | 页面骨架：侧栏、顶栏、五个页面容器、对话框；无脚本时的静态兜底文案也在这里 |
| `webui/src/main.ts` | 启动顺序、导航、顶栏与侧栏、页面渲染隔离 |
| `webui/src/text.ts` | 全部可见文案，中英成对，一处来源 |
| `webui/src/state.ts` | 语言检测、三个存储键的容错读写、探测模型默认值 |
| `webui/src/api.ts` | 同源请求、网关密钥通道、并发 401 只询问一次并各重试一次、错误文案映射 |
| `webui/src/data.ts` | 后端 JSON 的容错解析、目录会话内缓存、各端点包装 |
| `webui/src/store.ts` | 页面共享的视图状态与写操作（探测、切换、Orb、刷新） |
| `webui/src/format.ts` | 日期、金额、百分比、状态枚举到文案的映射 |
| `webui/src/ui.ts`、`dom.ts`、`dialog.ts` | 共享的加载/空/错误块、元素构造、唯一的模态实现 |
| `webui/src/pages/*.ts` | 五个页面各自的渲染与交互 |
| `webui/src/theme.css` | 全部样式与设计令牌 |

## 启动顺序与渲染隔离

顺序固定：先渲染框架（侧栏、顶栏、导航、语言开关、提示层、五个页面容器），再做语言检测与存储读取，再逐页渲染并各自发起请求，最后挂载时钟、可见性、地址片段监听。

每一页的渲染单独包在异常隔离里。某页抛错时，该页显示错误面（说明、原因摘要、重试、重新加载），其余页面、导航、语言开关不受影响。错误面本身也有兜底：即使构造错误面的 DOM 辅助函数也失效，容器仍会写入一行纯文本。异步更新中的异常只让对应视图进入错误态。模块顶层没有同步读取本地存储的代码，所以站点数据被禁用时页面照常渲染。

## 设计方向

**读者与场景。** 使用者是这台网关的运维者，在本地或内网打开一个一次性管理页：看账号是否还能用、令牌是否过期、额度还剩多少、模型目录有没有变化。任务偏「核对」而不是「运营」，所以界面按信息密度和可扫描性组织，不做仪表盘式的指标堆砌。

**配色（2 个核心色 + 1 个强调色）。** 纸色 `#f7f4ec` 与墨色 `#1d1c19` 承担全部背景与文字层级；强调色是赭红 `#9c3a1a`，只用在三处：当前页的导航标记、每页唯一的主操作按钮、以及需要立刻注意的横幅左边线。理由是这张页面几乎全程是文字与细线，强调色一旦铺开就会让「主操作」失去唯一性。成功、警告、错误三色只作为功能状态色出现在标签与提示的边框文字上，不参与装饰。

**对比度。** 正文墨色对纸色约 15.5 比 1；次要文字 `#59554c` 约 6.7 比 1；强调色作文字约 6.3 比 1；深色侧栏上的浅色文字约 15 比 1，侧栏次要文字约 9.7 比 1。全部超过 WCAG AA 的 4.5 比 1；大字与焦点环另有 3 比 1 以上的余量。禁用态用更浅的文字，但仍可辨认。

**字体与层级。** 标题用衬线体（Iowan Old Style / Palatino / Georgia / Noto Serif 栈），正文用系统无衬线，机器值（模型标识、路径、金额、时间、迁移键）用等宽体。三种字体各有一个明确的职责，层级靠字号、字重与留白区分，不靠阴影。衬线标题只在页面级与分区级出现，卡片内标题回到无衬线，避免整页都在「报头」腔调里。

**线条而不是卡片堆。** 账号、模型、检查项、路由都用「一行一项 + 细分隔线」的列表，而不是每项一张浮起的卡片。理由是这些列表动辄二三十项，卡片会带来大量重复的内边距和边框，反而降低扫描速度。账号因为字段多，用一张带细边框的容器承载，但内部仍是分隔线网格，没有阴影和圆角嵌套。

**圆角体系。** 只有三档：4 像素（标签、小方块、复选框式图标）、8 像素（按钮、输入框、列表容器、横幅）、12 像素（账号容器与对话框），外加 999 像素的胶囊用于状态标签。任何组件不得自取第四种圆角。

**间距体系。** 4 / 8 / 12 / 16 / 24 / 32 / 48 七档。列表行内边距固定 16，行与行之间靠 1 像素分隔线，不再叠加外边距。

**状态不能只靠颜色。** 额度状态有六种（仍有余量、额度耗尽、不公开数值、访问受限、账单暂不可得、令牌失效），探测状态有五种；每个都同时有图标（对勾、叉、感叹号、圆点）与文字标签，灰度下仍可区分。进度条除颜色外写出百分比数字，并以 `progressbar` 角色暴露数值。

**动效。** 只有两处：提示条展开的 160 毫秒高度过渡，以及加载指示的旋转。系统开启「减少动态效果」时两者都归零，旋转改为静态边框图案，进行中状态仍由文字说明（「正在…」）承担，不依赖动画。

**不采用的模板手法。** 没有渐变、玻璃、发光、彩色阴影；没有「标题 + 等大卡片网格」的首屏；没有伪终端窗口装饰（配置片段是真实可复制的纯文本块）；没有客户 logo 墙、统计数字堆砌、虚构的合规徽标。图标是一组 24 像素、线宽统一的内联矢量，纯装饰且对辅助技术隐藏。

## 五个页面

| 页面 | 地址片段 | 内容 |
| --- | --- | --- |
| 账号 | `#accounts` | 页头四个控件（探测模型、刷新账号状态、刷新 Orb 余额、探测全部账号）、成本说明横幅、四张指标、账号卡片列表、添加账号与登录区 |
| 模型 | `#models` | 目录刷新、说明横幅、模型行列表（显示名、标识、供应商、描述、默认档位与支持档位、上下文长度、选用按钮） |
| 诊断 | `#health` | 六项固定顺序的只读检查、逐项状态、汇总与完成时刻、重新检查 |
| 路由 | `#routes` | 三条协议入口与七组静态路由表，每条标注方法与是否需要网关密钥；本页不发请求 |
| 客户端 | `#clients` | 基础地址说明与四个可复制片段（Codex、Claude Code、OpenCode、命令行） |

导航前三个属于「运行」，后两个属于「开发」。当前页通过 `aria-current="page"` 与下划线标记，不只靠颜色。

## 双语与存储

语言检测：先读 `zed_lang`，只有精确的 `zh` 或 `en` 才采用；否则按 `navigator.language` 是否以 `zh` 开头判断。切换语言写入存储后重新加载页面，地址片段保留，因此停留在当前页。

只使用三个存储键：`zed_lang`、`zed_api_key`、`zed_probe_model`。全部读写经过 `state.ts` 的容错封装，读失败视为缺失，写失败被忽略但内存值继续生效。存储被禁用时：语言按浏览器判断、密钥只在本次会话有效、探测模型回到默认值 `gpt-5.6-luna`，页面五页与导航全部照常。不清理也不读取其他历史键。

## 网关密钥与 401

受保护请求统一带 `Authorization: Bearer <key>`；密钥为空时不带该头。任一请求收到 401 时打开页内对话框索取密钥：单字段、密码类型、可切换显示、Enter 提交、Esc 取消、空值拒绝。同一时刻只允许一个对话框，其他 401 等待同一结果；提交后每个请求各重试一次，重试仍为 401 则直接失败，不再二次询问，并记住被拒绝的密钥以免反复弹窗。取消则所有排队请求按原 401 失败，由各自视图显示错误态。

## 错误呈现

数据视图的失败统一是「发生了什么 + 可理解的原因 + 重试」。原因按状态码映射：400 请求被拒绝、401 密钥、403 拒绝、404 账号不存在、409 登录进行中、410 登录过期、413 过大、429 频繁、5xx 与网络失败为服务或上游暂时不可用。原始 JSON、堆栈、请求头、内网地址不进界面；机器式的短错误码（下划线串）只进控制台日志，不显示。

保留旧值的视图会标注「当前显示的是上一次成功获取的数据（时刻）」。写操作失败后按钮恢复可用，可再次点击。

## 接入片段

片段由运行时值生成：基础地址取当前页面的协议、主机与端口（无端口时回退 8001），示例模型取目录中的探测模型（目录不可用时回退到第一项，仍不可用则写 `<model-id>` 占位并提示自行替换），推理档位示例固定 `xhigh` 并说明可选档位见 `/v1/models`。密钥一律是占位符，从不读取本地存储。片段是可聚焦的等宽文本块，剪贴板不可用时可用键盘全选复制。

## 构建与兼容

- `npm ci && npx tsc --noEmit && npm run build`，产物是单个 `webui/dist/index.html`，不含外部域名引用，字体使用系统栈。
- 产物文本中五个页面锚点（`page-accounts`、`page-models`、`page-health`、`page-endpoints`、`page-integration`）各出现一次；后端 `src/http/static.rs` 的测试会检查它们。页面容器在 HTML 里静态存在，脚本只按这些容器渲染，不使用前端路由库。
- `build.rs` 在产物缺失时让构建失败并提示先构建界面。
